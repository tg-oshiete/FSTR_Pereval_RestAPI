# Контракт API

POST `/submitData/` создаёт новую заявку и возвращает HTTP 201 с `status: 201`,
`message` и `id`. GET `/submitData/{id}` возвращает заявку. PATCH того же пути
редактирует только `new` и возвращает `state: 1`; остальные статусы дают 409.
GET `/submitData/?user__email=...` возвращает массив с limit/offset и id ASC.

PATCH сохраняет пропущенные поля, поддерживает отдельные сезоны/компоненты coords.
null очищает необязательные строки и сезоны. images полностью заменяет фото,
[] очищает их. Пустой PATCH, неизвестные поля и изменение user запрещены.
Профиль одного email не перезаписывается; несовпадение данных даёт 409.

Фото — строгий base64 однокадрового JPEG/PNG с проверкой целостности и лимитов.
Валидация даёт 422 с detail.code/message/errors, где errors содержит loc/type/message.
Ошибки БД не раскрывают SQL или реквизиты. Запись заявки и дочерних данных атомарна.

Все схемы и ограничения доступны в `/openapi.json`. Публичное размещение этой
версии не предполагается; модель авторизации добавляется отдельно.
